# Code Review Instructions

## Component Context

Multiarch Tuning Operator — architecture-aware pod scheduling for multi-arch clusters. Uses scheduling gates, image inspection, and nodeAffinity mutation. Built with controller-runtime and Kubebuilder v4.

## Do Not Report

These are intentional patterns, CI-enforced, or generated:

- **Generated files**: `**/zz_generated*`, `config/crd/bases/**`, `config/rbac/role.yaml`, `bundle/manifests/**` — regenerated by `make manifests`, `make generate`, `make bundle`
- **Vendored dependencies**: `vendor/**` — managed by `make vendor`
- **Build tooling**: `hack/**` — CI scripts, not application code
- **Test utilities and builders**: `pkg/testing/builder/**`, `pkg/testing/framework/**` — test infrastructure
- **Kustomize configs**: `config/**/*.yaml` — base manifests, not hand-tuned
- **Formatting**: enforced by `make fmt` and `make goimports` in CI
- **Linting**: enforced by golangci-lint v2.12.2 (`make lint`)

## Required Checks

1. **API changes** → `make manifests generate` must be run; `make verify-diff` must pass
2. **Singleton constraint** → ClusterPodPlacementConfig name must be `"cluster"` (enforced at operator controller level, not webhook)
3. **Pod ignore logic** → Changes to `shouldIgnorePod()` must preserve hardcoded exclusions (operator namespace, `kube-*`)
4. **Scheduling gate mutation** → NodeSelectorTerm mutations must happen in webhook, not controller (Kubernetes rejects post-persistence changes)
5. **CGO dependency** → Image inspection requires `CGO_ENABLED=1`; do not add `CGO_ENABLED=0` to Dockerfile

## Severity Tuning

**High-churn files** (review carefully for regressions):
- `internal/controller/operator/clusterpodplacementconfig_controller.go`
- `internal/controller/podplacement/pod_reconciler.go`
- `internal/controller/podplacement/pod_model.go`
- `internal/controller/podplacement/scheduling_gate_mutating_webhook.go`

**API-sensitive** (verify backward compatibility):
- `api/v1beta1/*.go` — types and webhooks
- `api/common/plugins/*.go` — plugin types

## Path-Specific Rules

### `api/v1beta1/` — API Types and Webhooks
- New fields must have JSON tags with `omitempty` where appropriate
- Validation webhook checks plugin spec fields; singleton name is enforced by the operator controller
- Run `make manifests generate` after any type change

### `internal/controller/operator/` — Operator Controller
- RBAC markers in comments must match actual resource access
- Status condition updates must follow existing pattern (Available, Progressing, Degraded)
- Operand deployment changes require corresponding `handleDelete()` cleanup updates

### `internal/controller/podplacement/` — Pod Placement Logic
- Image inspection concurrency is `NumCPU * 4` — changes need performance justification
- Pod model changes must update all relevant labels and annotations in `pkg/utils/const.go`
- Webhook changes must handle informer cache lag (APIReader fallback pattern)

### `pkg/image/` — Image Inspector
- Registry auth changes must handle both pull secrets and global pull secret
- Must support OCI and Docker v2.2 manifest formats
- Changes to architecture detection must handle operator bundle images (arch-agnostic)

### `bundle/` — OLM Bundle
- Never edit CRDs directly — regenerate with `make manifests`
- CSV changes must preserve `relatedImages` completeness
- `make bundle-verify` must pass
